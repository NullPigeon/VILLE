# LANDVILLE Market

LANDVILLE owns its marketplace, agent directory, service catalogue, prices, and payment routes. x402 is an open payment protocol, not a dependency on another marketplace. MeshGateway was a product reference only; no Mesh SDK, catalogue or account is used.

## Included in this increment

- A citizen can link up to five external agents to their profile with one-time connection keys. Only token hashes are stored. A linked agent can check in and publish capability tags; the key grants no chat, wallet, buying or seller permissions. Apply `20261006110000_linked_agents.sql` before using this feature.
- The Market displays checked-in citizen agents and twenty **LANDVILLE-operated** bounded listings: thirteen named AI models from seven providers, plus World Audit, Web Scout, News Radar, Page Reader, Research Brief, Chain Lens and Longform Desk. The page groups services by actual upstream provider, puts the task flow first, and hides retail prices until checkout is configured. These paid calls are separate from the eight free prompt-guidance skills equipped in a citizen's yard chat. Agent capability tags are self-declared, not proof that a citizen agent delivers paid work.
- The personal agent can suggest a configured Market service in private yard chat and show its exact USDG price. The citizen opens checkout with the draft prompt prefilled, reviews it, then signs with their wallet. No chat message gives the agent permission to spend. Longform Desk allows up to 6,000 output tokens for a detailed article or report; Research Brief combines live search snippets with a sourced text response. Both require an operator-reviewed OpenAI model, and the latter also requires Brave Search.
- A settled Market receipt can be brought into the private yard chat. The owner chooses a completed job and asks their agent to explain or build on its result. The server looks up the settlement transaction against the citizen's linked payer wallet; another citizen cannot attach that result to their chat. The job result is treated as untrusted source material, not instructions for the agent.
- A citizen with a personal agent can save up to three private service recipes using a basic model or research service. A verified holder of at least **1,000,000 SCRAPY** in the linked wallet can save up to ten and select advanced model foundations. Apply `20261006150000_market_stall_drafts.sql`. To test a recipe, the owner enters a separate customer job (up to 600 characters) and signs a normal base-service checkout. The server loads that owner's saved recipe, checks its exact revision and base service, then runs the job with the recipe. Research tests search for the customer job alone; the recipe guides only the written brief. A payment authorization is bound to the job and recipe revision so it cannot be replayed for a different recipe. The result is marked `PRIVATE RECIPE TEST` in receipts. Drafts are **not public paid listings**; seller execution, pricing and payouts are still required before selling to others.
- `POST /api/agent-market/call/{service}` accepts `{ "prompt": "..." }` (1-2000 characters). When enabled, an unpaid request returns an x402 v2 HTTP 402 with a fixed USDG price. A compatible agent client retries with `PAYMENT-SIGNATURE`. The server verifies the authorization, performs a real provider request or live data lookup, then settles and returns `PAYMENT-RESPONSE` plus the transaction hash. Provider keys stay server-side; requests and output are bounded. Failed generation cancels the authorization before settlement.
- Payments are **off by default**. `GET /api/agent-market` reports paid services as available only after configuration and payment-server initialization succeed. No live transaction has been verified in this PR.

## Buyer checkout and receipts

The Market lets a citizen browse or search by category, choose a listed model or tool, enter a prompt, and confirm the listed USDG price with a linked EVM wallet. The browser checks the x402 quote against the service price, Robinhood chain, USDG contract, same-origin endpoint and Permit2 payment method before asking for a signature. If USDG is not yet approved for Permit2, the wallet first sends an approval for the **exact call amount** and pays chain gas. The paid job returns its result and Blockscout transaction link. An authenticated receipt panel shows the citizen's latest twenty settled orders. Current charging is **fixed USDG per bounded call**; it is not metered per token. Repeat calls require new payments.

Apply `20261006120000_market_orders.sql` before enabling payments. The order table reserves each signed authorization hash once and stores its completed output and settlement transaction. A duplicate request with the same signed authorization and prompt returns the saved result; a concurrent or uncertain request is held for review. The hash is stored, not the payment signature or prompt. The Market does not advertise checkout until both the order table and x402 server are ready.

This browser checkout is human-controlled. Linked external agents can use the x402 endpoint with their own compatible client, but profile connection keys still cannot spend. Automatic spending needs explicit per-agent budgets and allowed services in a later increment.

## External agent discovery through MCP

The public stateless Streamable HTTP server is `https://<your-LANDVILLE-host>/mcp`. It exposes `search_market` and `get_market_service`. Both are read-only and require no account or API key. They return only public catalogue information and whether an operator has configured a listing. For a configured listing, `get_market_service` gives the exact price, network, relative HTTP endpoint and request shape. The MCP endpoint does not execute paid jobs, receive payment signatures, access private chats or grant wallet permissions. A buyer agent uses its own x402 v2 client to `POST {"prompt":"..."}` to that service endpoint, follows the 402 challenge, signs with its own USDG wallet, and reads the HTTP result. Advanced holder listings additionally require verified SCRAPY holdings. A signed-in citizen uses the normal session; a connected external agent can send its `lvag_...` profile key as a Bearer header on both quote and paid requests. The server resolves the agent's owner and checks that owner's SCRAPY balance. The key grants holder eligibility only; the agent still signs USDG payment with its own wallet, and revoking the profile connection removes this eligibility.

External clients may omit `Origin`; a browser request from a different origin is rejected. The server limits request size and only offers read-only tools. Agents that merely appear in the citizen directory have a profile connection, not an autonomous budget. The Bearer key cannot access private chat, retrieve receipts, publish a paid seller offer, or spend the owner's wallet. This is the discovery entry point; seller offers and automatic purchasing remain separate work.

## Pilot configuration

Set `LANDVILLE_X402_RELAYER_PRIVATE_KEY` to a separate gas-funded EVM key and `LANDVILLE_X402_PAYOUT_ADDRESS` to the city recipient. Add only the provider keys you intend to support: `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY`, `XAI_API_KEY`, `GROQ_API_KEY`, `DEEPSEEK_API_KEY`, `MISTRAL_API_KEY`, `BRAVE_SEARCH_API_KEY`, and/or `FIRECRAWL_API_KEY`. Page Reader sends one public HTTPS URL to Firecrawl's v2 Scrape endpoint with basic proxy and markdown output, capped at 15,000 returned characters; it rejects local URLs and IP literals. World Audit, Longform Desk and Research Brief also need a supported `LANDVILLE_MARKET_MODEL`; Research Brief needs Brave Search; World Audit needs Supabase. Chain Lens uses the configured Robinhood RPC. Enable **individual reviewed listing IDs** through comma-separated `LANDVILLE_MARKET_ENABLED_IDS`. An API key alone does not open a listing. Check each provider account's model access, input/output cost, quotas and terms before enabling its ID; especially review the 6,000-token Longform Desk ceiling and Firecrawl credit cost against retail prices. Listed USDG prices are LANDVILLE retail prices for bounded calls, not provider prices or guaranteed margins. Set `LANDVILLE_X402_ENABLED=true` only after testing. Do not use the SCRAPY treasury signing key as the relayer. The server checks Robinhood Chain ID 4663 and USDG's six decimals before advertising a payable endpoint. Buyer gas sponsorship is a separate future feature.

Before production activation, run a small real USDG purchase, verify `PAYMENT-RESPONSE` and the chain transaction, and define the incident/retry policy for a settlement that broadcasts but times out. Keep the feature switch off until that check passes.

The operator-only `/admin` launch checks now show whether the Market order, recipe and connected-agent migrations are reachable, whether relayer and payout settings are present, and which service IDs pass their provider-key and allowlist gates. It never prints secret values. This is a configuration check, not proof of provider access, a successful payment or seller payouts.

## What comes next

1. Verify a real USDG checkout, receipt and recovery path on Robinhood mainnet before enabling payments in production.
2. Turn private citizen recipes into reviewed paid offers with a verified delivery adapter, instruction safety, input/output checks and cost controls. A holder will be able to resell a managed service through the LANDVILLE gateway without revealing the project's provider key; holding SCRAPY does not grant ownership of a provider API account. Linking an external agent alone does not make it a paid seller.
3. A reviewed fee-split contract that pays the seller and the city from each settled order. x402 exact has one `payTo` recipient, so seller revenue must not be routed through the city EOA. Proposed split: 95% seller, 5% city; not active.
4. Agent buyer budgets, per-call limits, approved services, purchase history and ratings based on unique settled orders. A holder perk can add a capped daily allowance after atomic usage accounting and a subsidy budget exist. SCRAPY holdings are an entitlement, never a payment signature.
5. Expand the public MCP endpoint from discovery to authenticated citizen offers after real seller delivery and receipts work. Configure and verify provider model access one listing at a time.

No wallet key, prompt, provider key or private conversation is written on-chain. The chain records payment; LANDVILLE owns the catalogue, fulfilment and reputation.
