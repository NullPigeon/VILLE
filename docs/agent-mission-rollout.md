# Personal robot World Job mission — local rollout

This local slice lets a yard owner start a bounded search for a public World Job. The robot considers only open jobs it does not own and the owner's published, configured services. OpenAI returns a structured pair or no match; the server validates both IDs and rechecks the job. A saved plan and durable journal record the scan, recommendation, approval and offer. The owner must press **Publish offer**. This does not buy a service or mark the job delivered.

## Before enabling

1. The `supabase/migrations/20261019120332_agent_mission_workflow.sql` migration was applied to the connected LANDVILLE project on 19 October 2026. The connector recorded version `20261019120332`. Read-only checks confirmed the mission, AI budget and encounter tables, the job-outcome trigger, and service-role-only access. Earlier migrations had been applied to this project without connector-visible history; reconcile that older baseline before relying on `supabase db push` to replay the entire directory. No user missions existed at verification time.
2. Configure `OPENAI_API_KEY` and optionally `LANDVILLE_AGENT_MISSION_MODEL`. Set `LANDVILLE_AGENT_MISSION_INPUT_USD_PER_MILLION` and `LANDVILLE_AGENT_MISSION_OUTPUT_USD_PER_MILLION` to that exact model's current rates. Set `LANDVILLE_AGENT_MISSION_DAILY_USD` and optionally `LANDVILLE_AGENT_MISSION_DAILY_CALLS` (default 3). Missing pricing fails closed before an AI call. The daily ceiling reserves a conservative amount before each provider request; reported token usage is also saved as an estimate. Timed-out calls keep their reservation because the provider might have billed them.
3. Keep the existing Market payout, seller wallet and service configuration working. The mission uses the same offer validation as the World Jobs API.
4. Set `LANDVILLE_AGENT_MISSIONS_ENABLED=true` on the site only after migration, Market setup, pricing and worker secret are ready. Set the same GitHub Actions variable and `LANDVILLE_SITE_URL` variable. `.github/workflows/agent-missions.yml` calls the worker with `LANDVILLE_WORKER_SECRET` every five minutes; it retries planning and approved offer publication after a 90-second lease expires, up to three attempts each. It first reconciles an already inserted offer before trying again.
5. From an owned yard, publish one eligible Market service, start a mission, review its selected job and service, then publish or cancel. Verify the journal and that only one offer exists in `landville_agent_job_offers`. Revisit the page to confirm state persists. Interrupt a planning request and check the worker resumes it. Repeat with a second owner's robot and eligible service targeting the same open job: one encounter should appear near Market and in both journals. When a buyer settles the exact offer, the same transaction records the outcome in the robot journal; the mission desk also reads the paid job and receipt. A completed job with another offer must appear as not selected.

The owner starts the search; the worker resumes interrupted planning and approved publication, but it does not invent goals. The owner can also retry publication: the offer helper returns an existing matching offer. A matched pair of robots appears beside a Scrap Race board on the map for 24 hours; this is an actual shared-job event, with no invented combat, payment or reward. Owner-editable memory, mission-driven travel and autonomous job execution remain later work.
